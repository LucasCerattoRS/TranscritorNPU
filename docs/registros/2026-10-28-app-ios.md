# App iOS (2026-10-28)

- Base: `2abd149` (main). Branch: `claude/android-iphone-adaptation-9jsxiz`.
- Pedido: usar no iPhone (13 Pro) sem computador, de graça; começar por baixar e transcrever vídeos do Instagram.

## O que mudou
- `ios/`: app SwiftUI novo. Login no Instagram dentro do app (WebKit, sessão do próprio usuário),
  download do Reel/carrossel pela API `/api/v1/media/<pk>/info/` (o caminho do yt-dlp com login),
  transcrição offline com WhisperKit 1.1.1 (large-v3 turbo comprimido ou small), saída .txt/.srt/.mp4
  visível no app Arquivos. Também transcreve vídeos da galeria e arquivos.
- `ios/Nucleo/`: lógica pura em Swift (código do link → id, leitura do JSON, erros, SRT e nome
  de arquivo portados do `app.py`), com 13 testes XCTest.
- `.github/workflows/ios.yml`: testa o `Nucleo` no Linux, gera o projeto com XcodeGen e compila o
  `.ipa` sem assinatura no macOS; em push, publica na release `ios-dev` para instalar pelo SideStore.
- `README.md` aponta para `ios/README.md` (instalação com Apple ID gratuito e uso).
- `.github/workflows/testes.yml`: pytest fixado em `<9.2`. O 9.2 apaga atributos de `MagicMock` ao desfazer
  o `monkeypatch`, o que quebrava 8 testes também na `main`.

## Testes
- `swift test --package-path ios/Nucleo` (Swift 6.2.1, Linux): 13 testes, 0 falhas.
- `python -m pytest -q test` com pytest 9.1.1: 42 passaram (com 9.2.0: 8 falham, igual na `main`).
- O app (UI, WhisperKit, WebKit) não compila no Linux; a compilação real é o job `ipa` do GitHub Actions.
